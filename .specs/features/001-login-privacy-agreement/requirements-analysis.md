# 需求分析说明书: 用户登录与隐私协议签署流程

**功能分支**: `001-login-privacy-agreement`  
**创建日期**: 2026-05-21  
**状态**: 草稿  
**输入**: 用户描述: "DevEco Code CLI 的用户登录和隐私协议签署流程，包含登录检查、隐私协议远程查询与签署、session 超时重试机制"

---

## 1. 简介

### 1.1 目的

本文档对 DevEco Code CLI 的用户登录与隐私协议签署流程进行需求分析，明确系统在用户首次使用或重新使用时，如何检查登录状态、查询华为云端协议签署状态、引导用户完成登录和协议签署，确保合规性要求得到满足。

### 1.2 范围

**包含**：
- 用户打开 CLI 时的登录状态检查与登录引导
- 华为云端隐私协议签署状态的远程查询
- 华为云端隐私协议的远程签署
- Session 超时后的 token 刷新与重试机制
- 协议版本比对逻辑
- 签署成功后的本地缓存更新
- 用户拒绝登录或协议时的退出流程

**不包含**：
- 具体的 OAuth 登录实现细节（已有 DevEcoAuth 模块实现）
- 具体的加密存储实现细节（已有 LocalCrypto 模块实现）
- TUI 具体渲染实现（已有 deveco-onboarding 模块）
- LLM 对话功能本身

### 1.3 假设和约束

| 类型 | 描述 |
|------|------|
| 假设 | 用户使用的网络环境可以访问华为云端协议服务（terms-drcn.platform.dbankcloud.cn） |
| 假设 | DevEcoAuth 模块已提供 accessToken 的获取与刷新能力 |
| 假设 | 本地 KV 存储机制可用，用于缓存协议签署状态 |
| 约束 | 协议 ID（PRIVACY_ID=10669, TERMS_ID=30000092）为华为指定，不可自行修改 |
| 约束 | 协议查询和签署 API 仅支持 POST 方法，参数格式固定 |
| 约束 | 仅支持中国大陆（country=CN）用户的协议签署 |

### 1.4 术语与缩写

| 术语/缩写 | 全称 | 说明 |
|-----------|------|------|
| DevEcoAuth | DevEco Authentication | CLI 内已有的华为账号 OAuth 认证模块 |
| PRIVACY_ID | Privacy Agreement ID | 隐私协议标识，值为 "10669" |
| TERMS_ID | Terms Agreement ID | 用户协议标识，值为 "30000092" |
| accessToken | Access Token | 华为账号认证后获取的访问令牌 |
| KV Store | Key-Value Store | CLI 内的本地持久化键值存储 |
| TMS | Terms Management Service | 华为云端协议管理服务 |
| session timeout | Session Timeout | API 调用时 accessToken 过期导致的会话超时 |

## 2. 系统上下文

### 2.1 系统定位

本功能位于 DevEco Code CLI 的启动入口层，是用户使用 CLI 对话功能的前置门控。用户必须先完成登录和隐私协议签署，才能进入对话页面。

### 2.2 系统边界

- **内部系统**：DevEco Code CLI（TUI 应用、DevEcoAuth 模块、KV Store）
- **外部系统**：

  - 华为 TMS 协议服务（协议查询与签署）

## 3. 需求分析概述

### 3.1 需求来源

- 业务合规要求：DevEco Code CLI 必须确保用户已签署华为隐私协议和用户协议后才能使用 AI 对话功能
- 产品设计文档：REQUIREMENTS.md 定义的完整流程
- 现有系统缺陷：当前实现仅使用本地 KV 存储标记隐私协议接受状态，未调用华为云端 API 进行远程查询和签署

### 3.2 需求目标

- 确保用户在使用 CLI 前完成华为账号登录和隐私协议远程签署
- 与华为云端协议服务对接，实时查询和签署协议，而非仅依赖本地标记
- 支持 session 超时后的自动 token 刷新与重试
- 支持协议版本比对，确保用户签署的是最新版本

### 3.3 关键利益相关者

| 角色 | 职责 | 关注点 |
|------|------|--------|
| CLI 用户 | 使用 DevEco Code CLI 进行 AI 对话 | 流程简洁、登录顺畅、协议签署清晰 |
| 产品经理 | 定义产品合规流程 | 确保合规性、流程完整性 |
| 合规团队 | 监督协议签署合规性 | 协议签署状态真实可靠、版本最新 |
| 开发团队 | 实现登录与协议签署功能 | API 集成稳定性、错误处理完备性 |

## 4. 需求场景分析

### 4.1 业务场景

#### 4.1.1 业务流程图

```
用户打开 CLI
    ↓
检查登录状态（DevEcoAuth.isLoggedIn）
    ↓
├─ 未登录 → 显示登录页面
│            ├─ 登录成功 → 检查协议签署（远程 API）
│            └─ 不登录 → 退出 CLI
│
└─ 已登录 → 检查协议签署（远程 API）
                ↓
             ├─ 已签署且版本最新 → 进入对话页面
             └─ 未签署或版本过期 → 显示协议签署页面
                                    ├─ Agree → 调用签署 API → 成功 → 进入对话页面
                                    │                       → 失败 → 重试/提示错误
                                    └─ Cancel → 退出 CLI
```

#### 4.1.2 业务规则

| 规则编号 | 规则名称 | 规则描述 | 优先级 |
|----------|----------|----------|--------|
| BR-001 | 登录前置规则 | 用户必须先登录华为账号才能进行协议签署查询和签署 | 高 |
| BR-002 | 协议版本比对规则 | 用户已签署版本号需 >= 最新版本号才算合规，否则需重新签署 | 高 |
| BR-003 | Session 超时重试规则 | API 调用返回 session timeout 时，需先刷新 token 再重试一次 | 高 |
| BR-004 | 本地缓存更新规则 | 签署成功后必须更新本地 KV 缓存；首次失败不修改缓存；重试失败也不修改缓存 | 中 |
| BR-005 | 拒绝退出规则 | 用户在任何步骤选择拒绝（不登录/取消签署），直接退出 CLI | 高 |

### 4.2 用户操作场景与关键路径

| UR-002 | 已完成用户 | 已登录且已签署最新协议的用户 | 直接使用对话功能 |

#### 4.2.2 用户操作场景

**场景 US-001: 新用户首次使用** (优先级: P1)

| 预期结果 | 用户重新签署最新协议，进入对话页面 |
| 异常处理 | API 调用 session 超时时自动刷新 token 重试 |

| 预期结果 | CLI 退出 |
| 异常处理 | 无 |

**场景 US-005: 已完成用户正常使用** (优先级: P1)

| 项目 | 描述 |
|------|------|
| 场景描述 | 已登录且已签署最新协议的用户打开 CLI，直接进入对话 |
| 前置条件 | 用户已登录，已签署最新版本协议 |

### 5.2 功能需求详细说明

#### FR-001: 登录状态检查

| 项目 | 描述 |
|------|------|
| 需求描述 | 系统在用户打开 CLI 时，通过 DevEcoAuth.isLoggedIn() 检查用户是否已登录华为账号。已登录则跳转到协议签署状态检查，未登录则显示登录页面 |
| 验收标准 | 1. 已登录用户跳过登录页面直接进入协议检查<br>2. 未登录用户显示登录引导页面 |
| 关联场景 | US-001, US-004, US-005 |
| 依赖需求 | 无 |

#### FR-002: 登录引导页面

| 项目 | 描述 |
|------|------|
| 需求描述 | 未登录用户看到登录页面，提供两个选项：1) 登录（打开浏览器进行 OAuth 登录）；2) 不登录（退出 CLI）。登录成功后自动跳转到协议签署状态检查 |
| 验收标准 | 1. 显示"登录"和"不登录"两个选项<br>2. 选择登录后成功完成 OAuth 流程<br>3. 选择不登录后 CLI 退出<br>4. 登录成功后自动进入协议检查 |
| 关联场景 | US-001, US-004 |
| 依赖需求 | FR-001 |

#### FR-003: 协议签署状态远程查询

| 项目 | 描述 |
|------|------|
| 需求描述 | 系统调用华为 TMS 协议查询 API（POST https://terms-drcn.platform.dbankcloud.cn/agreementservice/user），分别查询隐私协议（PRIVACY_ID=10669）和用户协议（TERMS_ID=30000092）的签署状态。每次调用传入 nsp_svc=as.user.query、accessToken 和一个协议 ID，共调用两次。两个协议均需版本合规才算通过 |
| 验收标准 | 1. 分别调用两次查询 API（PRIVACY_ID 和 TERMS_ID）<br>2. 成功调用 API 并正确解析响应<br>3. 正确判断 signInfo 是否为空<br>4. 正确判断 isAgree 字段<br>5. 正确提取 newestVersion 和 signed version<br>6. 两个协议均签署合规才算通过<br>7. session 超时时触发 token 刷新重试（关联 FR-007） |
| 关联场景 | US-002, US-005 |
| 依赖需求 | FR-001（需已登录获取 accessToken） |

#### FR-004: 协议版本比对

| 项目 | 描述 |
|------|------|
| 需求描述 | 系统比对每次查询返回的 newestVersion（最新版本号）与用户已签署的 signed version。隐私协议和用户协议需分别比对，两个协议均已签署且版本合规（signedVersion >= newestVersion）才判定通过；任一协议不合规即需重新签署 |
| 验收标准 | 1. 两个协议均已签署且 signedVersion >= newestVersion → 返回"已签署合规"<br>2. 任一协议 signedVersion < newestVersion → 返回"需要重新签署"<br>3. 任一协议 signInfo 为空 → 返回"需要签署"<br>4. 任一协议 isAgree=false → 返回"需要签署" |
| 关联场景 | US-002, US-005 |
| 依赖需求 | FR-003 |

#### FR-005: 协议签署页面

| 项目 | 描述 |
|------|------|
| 需求描述 | 显示隐私协议签署页面，包含：1) 用户协议链接和隐私协议链接；2) 确认框（可用空格勾选）；3) Agree 按钮（需勾选确认框后可用）和 Cancel 按钮。选择 Cancel 退出 CLI |
| 验收标准 | 1. 正确展示用户协议链接和隐私协议链接（统一展示）<br>2. 确认框可通过空格键勾选<br>3. 未勾选确认框时 Agree 按钮不可用<br>4. 勾选后点击 Agree 触发签署流程（同时签署两个协议）<br>5. 点击 Cancel 退出 CLI |
| 关联场景 | US-001, US-002, US-003 |
| 依赖需求 | FR-004（需判定需要签署才显示此页面） |

#### FR-006: 协议远程签署

| 项目 | 描述 |
|------|------|
| 需求描述 | 用户同意签署后，系统调用华为 TMS 签署 API（POST https://terms-drcn.platform.dbankcloud.cn/agreementservice/user），传入 nsp_svc=as.user.sign、accessToken、签署信息（包含 PRIVACY_ID 和 TERMS_ID 的 signInfo），完成协议签署 |
| 验收标准 | 1. 成功调用签署 API<br>2. 正确构造签署请求参数<br>3. 签署成功后进入对话页面<br>4. 签署失败时提示错误信息<br>5. session 超时时触发 token 刷新重试（关联 FR-007） |
| 关联场景 | US-001, US-002 |
| 依赖需求 | FR-005 |

#### FR-007: Session 超时重试

| 项目 | 描述 |
|------|------|
| 需求描述 | 协议查询或签署 API 返回 SESSION_TIMEOUT 或 INVALID_SESSION 错误时，系统自动调用 DevEcoAuth.refreshToken() 刷新 token，然后使用新 token 重试一次原 API 调用。如果刷新 token 后仍无法登录（getLoginFlag=false），则不再重试，返回失败 |
| 验收标准 | 1. 检测到 SESSION_TIMEOUT/INVALID_SESSION 错误时自动触发 token 刷新<br>2. 刷新成功后使用新 token 重试原 API<br>3. 刷新失败（getLoginFlag=false）时不重试，返回需要签署/签署失败<br>4. 重试成功时正常返回结果 |
| 关联场景 | US-002 |
| 依赖需求 | FR-003, FR-006 |

#### FR-008: 本地缓存更新

| 项目 | 描述 |
|------|------|
| 需求描述 | 协议签署成功后更新本地 KV 缓存（设置 deveco_code_privacy_accepted=true）。首次 API 调用失败且未重试时，不修改本地缓存。重试失败时也不修改本地缓存。签署成功（isUpload=true）时必须更新缓存 |
| 验收标准 | 1. 签署成功 → KV 缓存设置为 true<br>2. 首次失败未重试 → 缓存不变<br>3. 重试失败 → 缓存不变<br>4. 缓存更新后下次启动可利用本地缓存作为降级策略<br>5. 签署成功但缓存写入失败 → 仅记录日志，不阻断用户进入对话页面 |
| 关联场景 | US-001, US-002 |
| 依赖需求 | FR-006, FR-007 |

#### FR-009: 拒绝退出

| 项目 | 描述 |
|------|------|
| 需求描述 | 用户在登录页面选择"不登录"，或在协议签署页面选择"Cancel"时，CLI 直接退出，不保存任何状态变更 |
| 验收标准 | 1. 登录页面选择"不登录" → CLI 退出<br>2. 协议签署页面选择"Cancel" → CLI 退出<br>3. 退出时不修改任何本地状态 |
| 关联场景 | US-003, US-004 |
| 依赖需求 | FR-002, FR-005 |

## 6. 非性需求分析

### 6.1 系统定位

DevEco Code CLI 的合规门控模块，面向所有使用 CLI 的华为开发者，确保 AI 对话功能仅在合规条件下可用。

### 6.2 系统可靠性

| 指标 | 要求 | 说明 |
|------|------|------|
| 可用性 | 99.9% | 协议签署流程不应成为 CLI 启动的显著阻塞 |
| MTBF | >= 30 天 | 协议服务调用不应频繁失败 |
| MTTR | <= 5 分钟 | API 异常时通过 token 刷新快速恢复 |
| 故障恢复策略 | 降级至本地缓存判断 | 远程 API 不可达时：若本地 KV 缓存有已签署记录则允许进入对话页面；若无本地缓存记录则阻断进入并提示网络错误 |

### 6.3 安全隐私

#### 6.3.1 安全需求

| 安全类型 | 需求描述 | 安全等级 |
|----------|----------|----------|
| 身份认证 | 必须通过华为 OAuth 认证后才能查询/签署协议 | 高 |
| 数据加密 | accessToken 在本地存储时使用 AES-256-GCM 加密 | 高 |
| 传输安全 | API 调用使用 HTTPS | 高 |
| 访问控制 | 未登录/未签署用户无法进入对话功能 | 高 |

#### 6.3.2 隐私需求

| 隐私类型 | 需求描述 | 合规要求 |
|----------|----------|----------|
| 数据收集 | 仅收集协议签署状态（isAgree, version），不收集额外用户数据 | 华为隐私合规 |
| 数据存储 | 本地仅存储布尔型签署标记，不存储协议文本内容 | 最小化存储原则 |
| 数据使用 | 签署状态仅用于门控 CLI 对话功能入口 | 限定使用范围 |
| 数据共享 | 不与第三方共享签署状态数据 | 无第三方共享 |

### 6.4 可测试性

| 测试类型 | 测试要求 | 覆盖率目标 |
|----------|----------|------------|
| 单元测试 | 协议查询/签署 API 参数构造和响应解析 | 80% |
| 集成测试 | 完整登录→查询→签署流程 | 关键路径 100% |
| 端到端测试 | 模拟真实用户操作流程验证 | 关键场景 100% |

### 6.5 合规性

| 合规标准 | 适用范围 | 合规要求 |
|----------|----------|----------|
| 华为隐私协议 | 所有 DevEco Code CLI 用户 | 用户必须签署 PRIVACY_ID=10669 协议 |
| 华为用户协议 | 所有 DevEco Code CLI 用户 | 用户必须签署 TERMS_ID=30000092 协议 |

### 6.6 功能安全

不适用（非安全关键系统）。

### 6.7 用户资料需求

| 料类型 | 内容要求 | 交付时间 |

#### 7.2.4 风险评估与缓解措施

| 风险项 | 风险等级 | 影响范围 | 缓解措施 |
|--------|----------|----------|----------|

### Session 2026-05-21

- Q: 当华为 TMS 协议服务 API 完全不可达时，CLI 应如何处理？ → A: 允许进入（信任本地缓存）— 若本地 KV 缓存有已签署记录则允许进入对话页面；若无本地缓存记录则阻断进入并提示网络错误
- Q: 协议查询应如何调用（合并一次还是分别两次）？ → A: 分别查询两个协议 ID — 每次调用只传入一个 agrType，分别查询 PRIVACY_ID=10669 和 TERMS_ID=30000092，两个协议均合规才算通过

- Q: 签署页面应如何展示协议信息？ → A: 统一展示两个协议 — 签署页面同时展示用户协议和隐私协议链接，用户一次同意即同时签署两个协议
