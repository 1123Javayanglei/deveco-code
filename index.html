安装指南

系统要求

平台支持情况
Windows x64（推荐 Windows 11）✅ 支持
macOS Apple Silicon（M 系列）✅ 支持
macOS Intel（x64）✅ 支持

前置依赖

💻 Node.js / npm
前往 nodejs.org 下载安装 LTS 版本，安装后验证：node -v
🔨 DevEco Studio
需要 6.0+ 版本，提供编译工具链（hvigorw）和调试工具（hdc）
⚙ DEVECO_HOME
设置环境变量 DEVECO_HOME 指向 DevEco Studio 安装目录

将 DEVECO_HOME 设置为 DevEco Studio 安装目录，并将工具链路径添加到 PATH。配置后使用 echo $DEVECO_HOME 验证。

# 添加到 Shell 配置文件（如 ~/.zshrc、~/.bashrc）
export DEVECO_HOME="/Applications/DevEco-Studio.app/Contents"
export PATH="$DEVECO_HOME/sdk/default/openharmony/toolchains:$PATH"
# 系统设置 → 高级系统设置 → 环境变量
# 新建 DEVECO_HOME = DevEco Studio 安装路径
# 编辑 PATH，追加工具链路径

安装 / 卸载 / 更新

⚠ 必须使用官方 npm 源（--registry=https://registry.npmjs.org） 
npm install -g @deveco-test/deveco-code@beta --registry=https://registry.npmjs.org
deveco --version
# 第一步：清理运行时数据
deveco uninstall

# 第二步：卸载 npm 全局包
npm uninstall -g @deveco-test/deveco-code
# DevEco Code 支持自动更新
# 手动更新命令：
deveco upgrade
macOS 权限问题解决方案 
sudo -i npm install -g @deveco-test/deveco-code@beta --registry=https://registry.npmjs.org

安装后输入 deveco 启动，进入登录界面。登录后即可免费使用内置模型。

模型配置

在 DevEco Code 中输入 /models 进入模型配置界面。

使用免费模型

当前免费提供 GLM-5、DeepSeek-V3.2 两款模型（单账号每分钟 50 次请求限制）。

ℹ 当前在 build 模式下可正常使用，plan 模式下存在兼容性问题，待后续版本修复。

通过 Provider 配置

在模型选择页面按 Ctrl+A 进入 Provider 界面，选择提供商、输入 API Key、选择模型。

通过配置文件

编辑 ~/.config/deveco/deveco.jsonc（不存在则新建）。

💡 配置读取优先级：.deveco/deveco.jsonc > 项目目录 deveco.jsonc > ~/.config/deveco/deveco.jsonc 
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deveco": {
      "name": "DevEco Code",
      "models": {
        "glm-5": {
          "tool_call": true,
          "limit": { "context": 200000, "output": 8192 }
        }
      },
      "options": {
        "baseURL": "https://cn.devecostudio.huawei.com/sse/DevEcoCode/maas/v2",
        "apiKey": "{env:DEVECO_API_KEY}"
      }
    }
  }
}

配置多模态模型

多模态模型支持图片输入，有两种方式：

  • DevEco Code 内部：/models → Ctrl+A → 选择 ZhipuAI 或 Alibaba → 输入 API Key → 选择支持图片的模型
  • 配置文件：在 deveco.jsonc 的 provider 中新增带 modalities 字段的模型配置
多模态模型配置文件示例 
{
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "alibaba",
      "options": {
        "baseURL": "https://dashscope.aliyuncs.com/compatible-mode/v1",
        "apiKey": "xxxxxxxxxxxxxxxxxxx"
      },
      "models": {
        "qwen3.6-plus": {
          "tool_call": true,
          "limit": { "context": 200000, "output": 8192 },
          "modalities": {
            "input": ["text", "image"],
            "output": ["text"]
          }
        }
      }
    }
  }
}

Skill / MCP / 插件

🚀 Skill
全局技能定义，三种方式：目录放置、npx 安装、自定义创建
~/.config/deveco/skills/
🔗 MCP
外部工具集成协议，连接浏览器、数据库等第三方服务
deveco.jsonc
🧩 插件
社区插件扩展，如 Oh My OpenCode，npm 全局安装后在 deveco.jsonc 中配置
npm install -g
Skill 安装详情

方式一：目录放置

将 Skill 文件放入 ~/.config/deveco/skills/，重启后生效。

方式二：npx 安装

npx skills add vercel-labs/agent-skills

安装后存储在 ~/.agents/skills/ 目录。

方式三：使用 skill-creator

在 DevEco Code 内使用内置 skill-creator 创建自定义 Skill。

MCP 配置示例（Playwright） 
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "@playwright/mcp@latest"],
      "enabled": true
    }
  }
}
插件配置示例（Oh My OpenCode） 
npm install -g oh-my-opencode

在 deveco.jsonc 中配置插件入口文件路径：

{
  "plugin": [
    "<插件入口文件的绝对路径>"
  ]
}

自定义命令

支持 JSON 配置和 Markdown 文件两种方式定义自定义命令。

{ } JSON 方式
在 deveco.jsonc 的 command 字段中定义命令名、模板、描述、agent 和 model。
📄 Markdown 方式
在 ~/.config/deveco/commands/ 或 .deveco/commands/ 放置 .md 文件，文件名即命令名。
JSON 命令配置示例 
{
  "$schema": "https://opencode.ai/config.json",
  "command": {
    "test": {
      "template": "Run the full test suite with coverage report...",
      "description": "Run tests with coverage",
      "agent": "build",
      "model": "anthropic/claude-3-5-sonnet-20241022"
    }
  }
}

在 TUI 中运行：/test

生成 AGENTS.md

AGENTS.md 是当前工程的长期记忆文件，起到本地工程理解缓存的作用。建议在执行任务前先生成，可加速工程理解、提升运行效率。生成后会被 DevEco Code 自动加载使用。

SDD 模式

SDD（Spec-Driven Development）模式包含 5 个阶段：需求分析 → 架构设计 → 任务分解 → 代码实现 → 功能验证。

执行过程中在当前工程下新建 .specs/ 目录，每个需求依次生成 spec.md、plan.md、tasks.md。

切换模式

通过 Tab 键切换到 SDD 模式。

模拟器 / 真机配置

功能验证阶段需先配置模拟器或连接真机。参考 创建模拟器。

ℹ 不创建模拟器或连接真机时，功能验证阶段仅进行编译验证。连接真机需确保工程已配置签名。

UI 检查配置

功能验证阶段如需检查 UI，设置环境变量 ADDITIONAL_TOOL_GROUPS=ui_integration_test。

将以下环境变量添加到 Shell 配置文件或系统环境变量中：

# 添加到 Shell 配置文件（如 ~/.zshrc、~/.bashrc）
export ADDITIONAL_TOOL_GROUPS=ui_integration_test
# 系统设置 → 环境变量 → 新增用户变量
ADDITIONAL_TOOL_GROUPS=ui_integration_test
多模态模型配置（UI 检查）
  • 已登录：默认使用内置 Qwen2.5-VL
  • 未登录：跳过 UI 检查
  • 自定义：在 deveco.jsonc 配置（仅支持 Qwen 系列）

        "qwen3.5-flash": {

          "limit": { "context": 128000, "output": 4096 },
          "modalities": { "input": ["text", "image"], "output": ["text"] }
        }

    }
  },
  "agent": {
    "ui_verification": {

从 OpenCode 迁移至 DevEco Code

将 OpenCode 配置迁移到 DevEco Code，按以下对照表操作。

ℹ 以下路径均相对于 DevEco Code 配置目录（默认为 ~/.config/deveco/）
内容迁移目标路径支持 deveco.jsonc
Skillsskills/✅
Agentsagents/✅
Pluginsplugins/✅
MCP在 deveco.jsonc 中配置✅
主配置deveco.jsonc—
迁移命令示例 
# 将 OpenCode 的 skills 复制到 DevEco Code 配置目录
cp -r {源路径}/skills/* ~/.config/deveco/skills/
# 将 OpenCode 的 agents 复制到 DevEco Code 配置目录
cp -r {源路径}/agents/* ~/.config/deveco/agents/
# 将 OpenCode 的 plugins 复制到 DevEco Code 配置目录
cp -r {源路径}/plugins/* ~/.config/deveco/plugins/
# 将 OpenCode 主配置文件复制并重命名
cp {源路径}/opencode.jsonc ~/.config/deveco/deveco.jsonc

常见错误

1. Windows PowerShell 安装报错

原因：Windows 默认禁止运行 .ps1 脚本，npm 调用了 npm.ps1 被阻止。

推荐方案：修改执行策略

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
npm install -g @deveco-test/deveco-code@beta

备选方案：临时绕过或使用 CMD。

2. DevEco Studio Terminal 交互异常

原因：JetBrains 底座对 Terminal 的改造导致鼠标灵敏度和滚动条体验问题。

解决方案：使用 Windows Terminal 运行 DevEco Code。

3. 生成 nul 等异常文件

原因：模型错误应用了 Shell 命令，生成了无法常规删除的空文件。

解决方案：打开 Git Bash 进行删除。建议使用 CMD 运行。

4. Windows 10 全屏闪退

原因：conhost.exe 在处理 VT 序列时存在 Bug，全屏操作触发缓冲区溢出。

解决方案：安装 Windows Terminal（Microsoft Store 免费下载）。

5. Export 功能编码问题

原因：PowerShell 的 > 重定向默认使用 UTF-16 LE 编码，而 Import 使用 UTF-8。

解决方案：使用 CMD 执行导出和导入：

deveco export > session.json
deveco import session.json
